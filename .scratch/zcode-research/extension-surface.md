## Synthesis — the three duties

**Startup injection (dynamic text into a session at start).**
1. **SessionStart hook** is the only config-only surface that injects *dynamic, computed* text at session start: its stdout JSON `{"additionalContext": "..."}` (optionally with `hookEventName:"SessionStart"`) is appended to the message history on both startup and resume. Gated behind `hooks.enabled: true` unless a plugin contributes a hook. (PROVEN)
2. **AGENTS.md** (user + workspace) is the always-on *static* channel. (PROVEN)
3. **MCP servers** auto-connect at start from any scope, putting tool descriptions into context (workspace-scoped too — trust implication). (PROVEN)
4. **Skill descriptions** (`description`/`when_to_use`, ~250 chars shown) ride in the system prompt so the model can self-trigger. (PROVEN)
5. Slash commands inject text only when the user types `/cmd` (static body + `$ARGUMENTS`; no dynamic shell). (PROVEN)

**Param-triggered mid-session injection.**
**PreToolUse hooks** are the surface: they fire before tool execution, match on tool name (regex, with Task/Agent and Write/Edit/ApplyPatch aliases), receive the full `toolInput`, and can return `permissionDecision` (allow/ask/deny), `additionalContext` (appended to the tool result), or `updatedInput` (silently rewrites the tool's parameters). PermissionRequest is the second gate, at approval time. (PROVEN)

**Session-end records.**
No session-close hook exists. The closest is **Stop**, which fires at the end of *every assistant turn* and receives the full model response text (`responseText`, stdin `last_assistant_message`, and a one-line synthetic `transcript_path`), so it can record what the model said — and can even force up to 3 continuations with injected context. It cannot observe process exit; nothing is documented about surviving SIGINT/SIGTERM (docs suggest self-daemonizing for background work). (PROVEN for per-turn; UNPROVEN for exit survival)

**Biggest limitation:** config-file hooks are off by default (`hooks.enabled:true` required), and there is no true session-end/exit event — Stop is per-turn, so a "horizon" that must capture the final state of a session has no guaranteed last-word or shutdown signal through configuration alone.
